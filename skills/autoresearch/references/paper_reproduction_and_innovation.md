# Paper Reproduction and Innovation

本模块只要求在目标项目自己的数据集和 Benchmark 上复现论文方法；除非用户明确要求，不需要先在论文原始数据或原 Benchmark 上复现。普通 Candidate 的项目价值和晋升相对当前 Research Base 判断；Paper Repair 的局部改动相对 Experimental Parent 描述，但项目价值和晋升仍相对 Research Base 判断。

## 目录

1. 目标、启动条件与交付

3. 真实检索、下载与全文核验

## 目标

把论文调研变成可执行的算法实验，而不是泛泛的“可以借鉴”。对每篇论文先恢复其真正的创新机制，再将该机制放到目标项目中相同的功能位置，最后用独立审查筛选值得执行的实验和可能形成原创贡献的扩展。

固定区分三种产物：

1. **忠实复现（R）**：原论文算法和实现逻辑不变，只把训练/评估数据及任务标签实例替换为目标项目；也可写作“目标项目上的直接复现”，不属于原创。
2. **任务适配（A）**：只做兼容目标模型所必需、功能等价的接口改写，例如张量形状、token schema 或 adapter hook；不得改变状态/监督语义、可学习自由度、算子、目标函数、更新规则或信息流，通常不属于方法创新。
3. **新方法扩展（N）**：任何非兼容性必需的主动改动，或改变估计对象、状态/监督语义、训练信号、参数化、约束、优化过程、信息流或推理过程的改动，先标记为 `N candidate`。它还必须产生与近邻方法不同的可证伪预测，才能进入原创性审查。

不允许把 R/A 写成 N。新名称、换数据集、增加一个常规 loss、普通模块堆叠、换成 LLM judge 或加一个 gate，本身都不构成算法创新。

## 启动条件

开始前取得或从项目中查明：

- 目标项目目录、任务定义和标签口径；
- 当前最强基线及其数据、提示词、训练配置、指标和结果；
- 默认入选并深读 3–4 篇论文；用户如有数量偏好，只在 Bootstrap 对齐轮登记到 Research Brief 的允许行动区；
- 年份、会议、主题或接收状态限制；用户只说“最新/recent”时，默认检索当前年份及前两个自然年，并在研究合同中明示；
- 可用算力、时间和实验预算；
- 明确失败、反常结果、能力缺口或需要替换的组件。

Research Brief 冻结后，论文数量、检索式、来源和筛选参数均由 AI 在冻结边界内自主决定，无需再次确认。其余信息优先读取项目文件、实验日志和现有结果，不要让用户重复提供。

如果目标项目、基线或评价指标尚不明确，先生成 `Innovation Brief`，标出已确认事实和缺失信息；不要直接搜索论文。

## 工作目录与交付

若用户未指定输出目录，在目标项目下创建：

```text
research/llm_algorithm_innovation_<YYYYMMDD>/
├── papers/                         # 真实下载的 PDF
├── fulltext/                       # 提取的全文
├── paper_notes/                    # 逐篇证据卡
├── manifest.csv                    # 来源、版本、哈希、接收证据
├── 调研与创新点带入.md             # 主交付 1
└── 实验设计与优先级.md             # 主交付 2
```

主交付必须写入文件，不能只在聊天中总结。详细结构见 [paper_transfer_template.md](paper_reproduction/paper_transfer_template.md)。

## 阶段 1：锁定研究合同

建立 `Innovation Brief`：

- **任务**：输入、输出、监督信号、推理场景；
- **基线**：模型、可训练参数、loss、数据、预算、结果；
- **真实缺口**：哪项失败或限制有证据支持；
- **组件接口**：允许替换的位置；
- **不变量**：为公平比较必须保持一致的配置；
- **成功判据**：主指标、校准/效率指标、统计要求；
- **禁用主张**：数据当前无法支持的构念或因果说法。

不要从论文标题反推项目缺口。研究合同必须来自项目事实。

## 阶段 2：真实检索、下载与全文核验

### 2.1 预注册纳排标准

搜索前写清年份、会议、正式接收状态、主题范围、排除条件和目标数量。若用户要求“顶会论文”，使用官方 proceedings、会议 accepted-paper 页面或官方 OpenReview decision 验证；不要把 arXiv-only、withdrawn、workshop 或 submitted 稿件混入。

### 2.2 建立候选池

至少使用两条互补检索路径：

- 任务路径：目标任务、数据结构、监督形式和失败模式；
- 组件路径：PEFT/LoRA、objective/loss、optimization、data selection、RL/post-training、memory、routing/MoE、multimodal/fusion、calibration、temporal modeling、inference-time computation 等。

优先原论文和官方来源。搜索结果页、博客和二手解读只能用于导航，不能作为方法证据。

候选池初筛完成后，只选择当前最相关、最值得进入实验链路的 3–4 篇论文。只有这 3–4 篇必须下载并深读全文；能够通过标题、摘要或任务口径明确排除的候选不要求下载。若不足 3 篇合格论文，如实记录实际数量和缺口，不得降低标准补足。

论文组合由 AI 根据当前瓶颈自适应决定，不使用“直接方法、组件方法、正交方法”之类的固定名额。优先保证相关性、全文质量、可实现性和机制证据；在质量相当时，优先选择能提供互补机制、不同 Intervention Locus 或竞争解释的论文，避免多篇论文只重复同一机制而没有新增信息。AI 必须简要说明入选组合为什么足以支撑下一轮候选，但不得为了形式上的多样性选入明显更弱或无法迁移的方法。

文献检索既可以由 Frontier 为空或分支关闭触发，也可以由成功实验产生的新问题触发。后一种情况必须先明确具体 Research Question，例如新底座暴露的瓶颈、需要替换的组件、尚未解释的 loss 行为或缺少证据的竞争机制；不得用无决策目标的持续检索代替实验判断。

### 2.3 下载和验证

对每篇入选论文：

1. 保存 PDF 到 `papers/`；
2. 记录官方接收页、PDF URL、下载日期和版本口径；
3. 检查文件头、MIME/file type，确认是 PDF 而非挑战页或 HTML；
4. 用可用 PDF parser 打开文件并读取页数，记录 parser 与结果；
5. 记录 SHA-256、页数和文件大小；
6. 提取全文到 `fulltext/`，记录抽取工具、状态和字符数，并抽查方法页文本是否可读；
7. 将验证命令/工具、输出摘要和失败原因写入 manifest 或逐篇证据卡；
8. 若使用作者预印本而非 camera-ready，明确标注，不能声称逐页等同正式版本。

缺少可读全文的论文不得进入“已深读”集合。下载失败要记录原因并替换候选，不能用摘要补位。

## 阶段 3：逐篇恢复创新机制

每篇论文使用一个独立阅读任务。若 subagent 可用，默认一篇一个 reviewer，在运行时允许的并发限制内分批执行；若不可用，进行隔离的逐篇阅读并披露限制。阅读者不得只看摘要，至少锚定 5 处正文证据，包括方法定义、核心公式/算法、关键实验、消融和限制。

逐篇建立 `Mechanism Fingerprint`：

| 字段 | 必须回答的问题 |
|---|---|
| Problem | 论文真正解决的技术瓶颈是什么？ |
| Baseline | 它从哪个标准方法出发？ |
| Intervention locus | 改动发生在数据、参数、状态、loss、优化、推理还是评估？ |
| State and signal | 输入什么状态，使用什么新增信号？ |
| Operator | 新增或改变了什么算子、参数化或更新规则？ |
| Objective | 核心目标函数和约束是什么？ |
| Causal mechanism claim | 作者为什么认为它会改善目标？ |
| Evidence | 哪个主结果和消融支持该机制？ |
| Dependencies | 代码、标签、模型、算力和前置条件是什么？ |
| Limits | 哪些场景未验证或失败？ |

随后写一段连续的中文方法描述，必须包含“流程、创新位置、训练/推理变化、与原基线的本质差异、证据”，不能只列项目符号。

## 阶段 4：机制保持的项目带入

### 4.1 选择迁移层级

- **全方法迁移**：目标任务与论文问题、监督和输入输出同构，算法流程无需修改；即使数据集不同，也可分类为目标项目上的 R。
- **组件迁移**：论文创新只作用于 LoRA、loss、sampler、memory、router 等局部组件，只替换目标项目对应组件。
- **协议迁移**：论文核心是训练课程、评估协议或数据构造，迁移协议而不伪装成模型结构创新。
- **不可迁移**：关键监督、数据或假设在目标项目中不存在；明确 No-Go，不强行类比。把它记录为 screened-out candidate，并补选可迁移论文，直至达到默认 3–4 篇或 Brief 已冻结的数量偏好；固定且不可替换的论文只保留 No-Go 说明，不强行生成实验。

### 4.2 完整映射

对每篇填写：

```text
论文变量/模块  -> 目标项目变量/模块
原输入信号     -> 目标项目可获得的对应信号
原更新规则     -> 目标训练循环中的具体位置
原目标函数     -> 目标项目中的完整公式或伪代码
原对照组       -> 目标项目中公平的基线
原机制预测     -> 目标指标、切片或交互上的方向性预测
```

同时维护 `Delta Ledger`：

| 原论文操作 | 目标项目操作 | 是否仅为兼容所必需 | 是否改变函数映射/目标/可学习自由度 | 分类依据 |
|---|---|---:|---:|---|

只有数据/标签实例替换时为 R；存在功能等价且必要的接口改写时为 A；任一主动改动或语义/目标/自由度变化都先归为 N candidate，不允许靠命名选择类别。

带入描述必须具体到代码/模块接口层面。例如论文创新 LoRA，就说明替换哪些 projection、rank/初始化/更新规则如何变化，以及 E08 类基线的哪些配置保持不变；不能只写“在本项目使用该 LoRA”。

### 4.3 机制保持测试

迁移实验进入清单前回答：

1. 去掉论文特有算子后，是否退化为目标项目现有基线？若不能，映射可能不忠实。
2. 论文中的信息流或优化压力在目标项目中是否仍然存在？
3. 哪些改变只是数据实例替换，哪些属于接口适配，哪些改变了原机制？
4. 哪项结果会支持该机制，而不仅是说明模型分数偶然提高？
5. 哪项结果会证伪迁移假设？

任一问题无法回答，标记 `transfer fidelity = low`，不得进入高优先级。

随后写一段连续的中文带入描述，包含目标基线、替换位置、完整信号流、训练/推理流程、预期机制和公平比较方式。

## 阶段 5：形成论文方向候选池

完成 Mechanism Review 后，只有通过迁移硬门、且相对当前 Research Base 仍具有独立判别价值的论文，才生成初始主复现候选；单篇论文初始最多生成一个主候选。入选论文共同形成动态方向池，不构成必须逐篇完成的任务清单，也不得先把多篇论文混成一个“综合模型”。每个主候选先回答：

> 如果把这篇论文的创新机制忠实移植到当前项目，它是否仍有效，为什么？

实验卡必须包含：

- ID、来源论文和 R/A/N 类型；
- 可证伪假设及至少一个竞争解释；
- 当前基线和唯一主要改动；
- 固定项、允许调节项和公平预算；
- 数据划分、泄漏检查和实验单位；
- smoke、完整运行和必要 seeds；
- 主指标、次指标、机制切片、效率指标；
- 强基线、负对照和最小充分消融；
- 支持预测、证伪预测和明确 No-Go 条件；
- 资源、预计时间、依赖与可复现 artifact；
- 允许与禁止的论文措辞。

先做最低成本但能区分假设的实验，不以“大训练”代替判别力。复杂多因素方案先做筛选设计，再验证存活因素的交互，避免同时改变多个组件后无法归因。

Controller 每次只从 Active Frontier 选择唯一下一实验，不要求按论文顺序运行全部候选。某个结果触发 Research Base 晋升后，必须先完成晋升确认，再让全部尚未运行的论文候选相对新底座重新审查：

- 仍能提供新机制、解决不同瓶颈或具有更高信息价值的候选可以继续保留；
- 已被新底座吸收、相对优势消失、机制重复或不再公平可比的候选转为 HOLD、关闭或重新定义；
- 当前成功路线只有在下一步仍具有新的可证伪假设时才继续深入，不得因为已经涨点而无限占用预算；
- 后续开始退化为重复调参、增益衰减或无法产生新机制认识时，返回 Active Frontier 选择其他论文或新方向。

## Paper Repair Cycle

忠实 R/A 复现在目标项目上效果不佳时，不立即放弃论文方向。AI 可以基于论文机制、消融证据和新近方法验证最多三个核心修复假设：

- 每次只修复一个过时、不合理或不适配的主要组件；
- 主动替换论文原组件后，该实验属于 N candidate，不再称为忠实 R/A；
- 相对 Experimental Parent 判断局部修复是否有效；
- 相对当前 Research Base 判断整个方向是否具有项目价值；
- 显著优于失败的 Experimental Parent 不能替代 Research Base 晋升条件；
- 三个核心修复均失败后关闭该 Paper Repair 分支并回溯。

修复实验只维护一套五维分类，描述相对 Experimental Parent 的本次局部改动；Experiment Card 同时记录相对 Experimental Parent 和 Research Base 的结果，不额外创建 Project Classification 或 Repair Delta 文档。

## 阶段 6：从复现候选生成新扩展

首次规划可以基于已验证论文机制和项目已有失败证据生成“假设阶段 N”，但必须标为 `pre-experiment`，不能写成已证实创新。若扩展依赖“迁移后仍然失败”的观察，则必须等对应 R/A 实验完成后再生成；获得真实结果后，才生成或升级为 `results-grounded N`。读取 [prompt_patterns.md](paper_reproduction/prompt_patterns.md)，优先使用下列算子：

1. **目标矛盾**：现有方法必须在两个目标间取舍，能否引入新的状态、约束或优化几何解除矛盾？
2. **残余失效**：论文机制迁移后仍系统失败在哪个 slice？该残差是否指向新估计对象？
3. **假设反转**：论文依赖的核心假设若不成立，什么训练规则仍然有效？
4. **尺度或层级迁移**：样本级机制能否变为节点级、患者级、层级式或跨时间机制，并产生不同预测？
5. **机制组合**：仅当组合产生新的可识别状态、约束、闭式性质或优化过程时保留；普通串联直接淘汰。
6. **困难样本精炼**：用冻结开发集上的失败案例更新候选，但保留淘汰历史，避免追逐单一验证集。

每个 N 类候选必须给出：证据阶段、最窄创新句、最近 3–5 个近邻、逐项差异、不可被重参数化/简化回已有方法的理由、判别预测和首个最小实验。近邻搜索必须保留查询、日期、数据库、主来源 URL、版本、可读全文和方法锚点；证据账本不完整时令 `novelty_status=unclear`，但另行判断实验是否值得执行。若当前没有合格 N 候选，在主文档中明确写“deferred”，不要凑数。

## 阶段 7：候选审查与排序

普通论文候选读取 [experiment_ranking_rubric.md](paper_reproduction/experiment_ranking_rubric.md)，由当前主 AI 在同一次 Research Graph Controller 调用中执行一次 `REVIEW`。不启动独立 agent、投票或人工审批，也不生成独立 Review 文档。

REVIEW 必须同时检查：

- 论文机制是否被忠实迁移；
- 最近邻证据是否使“创新”坍缩为已有方法；
- 可执行性、公平性、泄漏、消融、统计和信息增益；
- R/A/N 分类、候选优先级、一句话理由和下一图操作；
- 哪个最小实验能够最快证伪假设。

硬门优先于总分：

- 无机制差异、无判别预测、无失败条件或无最小实验：不得进入 shortlist；
- 迁移忠实度不足：退回重写；
- 近邻碰撞未排除：结构分类仍保持 N candidate，但 `novelty_status=unclear`；
- 数据泄漏或比较预算不公平：No-Go；
- 通过硬门后，再按“预期信息增益 / 成本”、机制价值和执行依赖做 Pareto 排序。

只有跨分支 A+B 的 `MERGE` 候选使用 Research Graph Protocol 规定的 Interaction Review Gate 和三个独立 subagent。

## 阶段 8：写两个主文档

### 调研与创新点带入.md

必须包含研究合同、检索与版本口径、逐篇方法段落、逐篇带入段落、机制映射表、忠实度判断，以及 R/A/N 分类。事实和推断必须分开；每个方法主张带页码、公式、算法或表格锚点。

### 实验设计与优先级.md

必须包含逐篇主实验卡、新扩展候选或明确的 deferred 状态、主 AI REVIEW 结论、硬门淘汰原因、最终排序、首批执行队列和停止规则。排名不能只给分数，必须解释为什么前一个实验比后一个更能降低关键不确定性。

## 质量闸门

交付前逐项验证：

- [ ] 入选数量符合默认 3–4 篇或 Brief 已冻结的数量偏好；不足三篇时已如实记录证据缺口；
- [ ] 入选数量只统计可迁移论文，screened-out candidate 已替换或说明固定论文例外；
- [ ] 每篇都有可读 PDF、全文、哈希、版本说明和文件/解析/抽取验证回执；
- [ ] 每篇均有正文证据锚点，不是摘要复述；
- [ ] 每篇均有一段完整方法描述和一段完整带入描述；
- [ ] 每篇入选且可迁移论文对应一个独立主实验；
- [ ] LoRA/loss/架构等创新映射到正确组件，而非笼统类比；
- [ ] 每个映射都有 Delta Ledger，R/A/N 分类没有偷换；
- [ ] 新扩展标明 pre-experiment/results-grounded/deferred，并完成带全文与方法锚点的最近邻证据账本；
- [ ] 每个入围实验都有竞争解释、证伪条件和最小实验；
- [ ] 普通候选已由主 AI 完成一次 REVIEW；MERGE 候选已按 Interaction Review Gate 完成三方审查；
- [ ] experiment_decision 与 novelty_status 分列，实验 Go 未被写成原创性成立；
- [ ] 两个主文档和所有链接可读；
- [ ] 下载、抽取、审查或验证失败均被如实记录。

不要为了凑足数量降低纳入标准。若合格论文不足，报告实际数量和缺口，由用户决定放宽条件。
