# 审稿意见拆解与回复规划

先读审稿意见和论文，拆解原子问题，再组织实验线与回复线，最后生成 LaTeX 骨架。输出定位为供作者判断的建议；未经证据核实，不作修改已完成、结果已获得或机制已证明的断言。

## 配套材料与范围

读取 [返修规划说明](references/revision-planning.md)，按作者确认的流程组织问题与工作顺序。需要进一步判断拆分和合并粒度时，可参考 [Paper2Rebuttal 原子问题提取提示词](references/issue_extractor.yaml)。各文件的来源和调整见 [来源说明](references/provenance.md)。

执行以本入口为准。返修规划说明补充具体判断方法；外部提取提示词仅作参考，适用以下要求：

- 仅完成解析、拆解、策略规划和回复骨架；不进入完整 rebuttal 撰写阶段。
- 按实际投稿阶段处理，不默认 ICML、纯文本、五天期限或固定字数分配。版面要求缺失时可继续规划并标注待核实。
- 保留每条原始意见。纯赞扬可记为“无需实质回应”；伦理、置信度等栏目的具体疑问仍须提取，不按栏目名过滤。
- 只有核心问题和回应证据相同才归组；“都不清楚”不足以合并不同的方法问题。
- 不把建议补实验视为已授权运行，不预设实验会优于基线，不编造结果、文献或正文位置。
- 不推测 reviewer 的正面或负面立场；推断核心担忧时说明原文依据与不确定性。

## 1. 读取和定位

读取完整审稿意见与可用论文版本，记录材料版本、轮次和已读范围。核对研究问题、样本或系统、方法、指标、主张与实际证据。按需读取相关附录和已有结果。

原文材料不全时，先拆解能够确认的部分，把论文对应位置标为“待核实”，不要虚构章节或结论。区分原投稿稿、当前修订稿、作者计划和已验证结果。

在用户指定的输出目录创建以下文件；未指定时使用项目下独立的 `review-plan/`。复用已有输出时保留原始记录、稳定 ID 和作者修改，不覆盖作者写好的回复。按轮次增量更新。

- `REVIEWS_RAW.md`：审稿意见原文、原编号和材料来源。
- `ISSUE_BOARD.md`：原子问题、来源、论文证据和状态。
- `STRATEGY_PLAN.md`：两条工作线、依赖关系、共同主题、每个 comment 的建议逻辑。
- `response/`：从 [模板目录](assets/latex-template/main.tex) 复制并填充的独立 LaTeX 项目。

## 2. 最小原子问题

保留 `R1-C2` 等原 comment ID，为其子问题分配 `R1-C2-a`、`R1-C2-b`。AE/Editor 使用独立前缀。拆分标准是“一项可独立回应和核验的要求”，不是按每个句子或每个名词拆分。

按以下标准拆分和归组：

- 一条评论同时质疑速度和准确率，拆为两个问题。
- 同一个问题的理由、例子、解释通常一起保留。
- 不同基线、不同变量或不同证据需求分别记录。
- 多条评论提出同一问题，建立一个共享 `group_id`，保留全部原子 ID 和原文锚点。不得合并掉单条意见的独特要求。

每个原子点记录：

| 字段 | 内容 |
|---|---|
| ID / 原文锚点 | reviewer、轮次、原 comment、子问题及原文短引 |
| 字面要求 / 核心担忧 | 可核查要求，以及有依据的担忧解释 |
| 论文对应 | 已核对的章节、表格、公式、结果或“待核实” |
| 证据状态 | 已有证据、待查证材料、需要新增的分析或实验 |
| 证据来源 / 行动承诺 | paper / review / verified_result / author_reported / missing；每项行动标注 suggested / approved / completed_verified |
| 处理建议 | 澄清、正文修改、数据审计、补分析、补实验、说明边界 |
| 关联与难度 | group_id、前置依赖、难度、是否影响其他意见 |
| 状态 | open / needs_evidence / planned / verified / deferred |

`verified` 表示该原子点所需证据已经核实，不等于回复已写完。明确记录建议和作者决定的区别；数据审计、消融、描述性分析各自能回答的问题不同。

新增行动默认 `suggested`，只有已有明确授权才能标为 `approved`，完成并核实后才能标为 `completed_verified`。作者口头报告结果应标为 `author_reported`，与已读到原始产物的 `verified_result` 区分。尚未授权不妨碍继续规划其他问题，但不得把建议写成作者的承诺或已完成事实。

## 3. 两条工作线

### 实验线：最先识别和安排

先扫描全部原子点，列出确实需要新增证据的项目，再写逐条回复逻辑。每项包括实验 ID、关联原子点、要消除的疑问、已有证据为何不足、最小可行设计、依赖与成本估计、可能结果及相应解释边界。

区分“必须补充以支持核心主张”和“可选增强”。现有材料或收紧主张足以解决时，不自动扩大为新实验。默认先满足前置依赖，再安排耗时长、难度高、影响多个评论的任务；独立小任务可穿插。实际顺序允许作者调整。

以回答科学问题和保证协议有效为验收标准，不以达到某个有利数字为标准。只提出计划；运行代码、使用付费资源和提交远端作业遵循用户另外给出的授权。

### 回复线：简单到复杂、个别到综合

先为需要补实验的评论搭建参考逻辑和证据占位，再为不需要补实验的评论构思。各组内由简单到复杂、由单个问题到跨评论综合问题。显式依赖优先；会决定全篇口径的核心问题可提前。

区分“构思顺序”和“完成回复顺序”：实验未完成的原子点保持 `needs_evidence`；等待已授权实验运行时，可继续构思或整理不依赖其结果的评论。两线通过实验 ID 和原子 ID 关联，结果返回后仅更新相关条目。

识别共享主题，允许一条逻辑链覆盖多个原子点，也允许多个 comment 对应同一问题。回复信中保留原 reviewer/comment 顺序，在每条下呈现其原子点；通过关联编号指向共享证据，避免遗漏、矛盾和复制长段文字。

在 `STRATEGY_PLAN.md` 分别列出实验队列、回复构思队列和跨 comment 分组，说明必要的排序例外。不得把规划文件的排序自动变成对审稿原文的重排。

## 4. 每个 comment 一份参考逻辑

为每个完整 comment 写一条简短中文论证链，覆盖其全部原子点。默认一句、2 至 4 个环节；只有压缩会损失关键含义时才略作展开。内容必须结合该论文，避免所有意见套用同一句“核对证据、说明边界”。

在 LaTeX 中写成：

```latex
%% 建议回复逻辑（供作者参考）：
%% [基于论文的起点] → [对应问题的证据或待核实环节] → [可支持的解释及拟修改位置]。
```

每个 comment 只出现一次该注释。原子点下不重复生成逻辑链。共享主题可在该处注明关联 comment ID；当实验结果尚未知，写“待结果核实后判断”，不预写有利结论。

## 5. LaTeX 输出

使用 `assets/latex-template/` 中的 `main.tex` 和 `paper.tex`。保留开头长表、comment 框、Response 标题、原子点 `\textbf{(a) ...}` 英文小标题以及回复占位符。

- 在 comment 框内，把忠实中文翻译注释放在对应英文原文上方。长评论可逐段对照，保持完整覆盖。
- 忠实保留否定、条件、程度、比较对象、数字、引用，以及 may/should/must 的语气差别。不得把“可能存在混杂”翻成“存在混杂”，不得在翻译中添加辩护、评价或潜台词。
- 若原文歧义未解，在翻译之外的“翻译待核实”注释中标明，不擅自改写其含义。
- 原子问题说明和小标题中文注释放在英文小标题上方。标题描述问题，避免预设已证明、已消除混杂等结论。
- 每个原子点下只放 `[Response to be completed.]`，不生成“回复中文对应：[待填写。]”注释，也不写完整回复正文。
- 开头表格采用“拟修改内容”或明确占位符。只有核实完成后才能改成“已完成修改”。
- 原文保存在 `REVIEWS_RAW.md`；LaTeX 中只做显示所需的转义，不更改语义。普通文本中的 `% & _ # $ { }` 分别使用 `\% \& \_ \# \$ \{ \}`；字面反斜线、波浪号和脱字符使用 `\textbackslash{}`、`\textasciitilde{}`、`\textasciicircum{}`。保留已有效的数学环境；URL 使用 `\url{...}`，代码文本按语境处理，避免重复转义。逐段核对编译后的可见原文。
- 每一行中文注释均以 `%` 开头，不能意外排入 PDF。
- 分清通用模板与实际用户输出：分发模板仅含虚构示例和占位符；具体任务的私有输出保留该用户提供的真实评论。

## 6. 核验与停止

核对原 comment 数量、原子 ID、共享主题和实验映射，确保每条原文有去向。逐条对照翻译与英文，检查是否新增了主观判断。检查建议逻辑的数量是否等于 comment 数量，且英文小标题覆盖全部原子点。

编译 `response/main.tex`，优先使用现有本地工具：

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
# 或
tectonic main.tex
```

检查 PDF 的开头表格、跨页评论框、标题和占位符；中文注释应不可见。核对无未定义引用、缺文件、越界表格或被吞掉的英文原文。无可用编译器时明确报告未编译。

交付台账、两线计划和可编译回复骨架后停止。报告证据缺口、未决事项及验证范围。后续完整回复写作、正文修改、实验运行和远端同步均为另行指定的工作阶段。
