# Benchmark 与方法选择

## 方法集合

常见组内部覆盖简单诊断方法、经典家族、主流架构与现有项目方法，合计 5–10 个；近期组默认约 3 个，强调相关机制和可执行性。seed、超参或同一方法的普通变体不是新的独立方法。

检索时先注明任务关键词、机制关键词、年份窗口和截止日期。用户未指定近期范围时，先查看当前及前两个自然年的相关工作，若任务更新慢则扩展并解释。通过官方论文/仓库确认版本、方法和代码状态；不能把搜索排序、年份或引用量当作效果证据。

遇到不适用方法，写出缺失输入、标签、预算或假设。允许解释合理缺席、寻找替代，但不能为了达到数量改坏原方法或暗中减少任务。报告分母：选中多少，实际完整运行多少，可比多少，失败/未跑多少。

## Benchmark Contract：结果出现前确定

| 项目 | 必须明确的事实或决定 |
|---|---|
| 任务与数据 | 输入、输出、标签、版本、包含/排除、预测时可见信息 |
| 划分 | 训练、开发、最终测试；用户/源文档/时间等独立单位；去重与泄漏检查 |
| 预处理 | 哪些操作在训练集拟合；允许的方法专用处理及其理由 |
| 指标 | 主指标、方向、单位、汇总方式；必要的成本/机制指标 |
| 选择规则 | 开发集、调参空间和机会、checkpoint、停止与平局规则 |
| 资源 | 训练、调参、重复与近期方法的完整成本；硬件和授权上限 |
| 不确定性 | seed 重复与样本/用户依赖分别处理；重复数理由 |
| 异常 | 数值失败、OOM、访问失败、缺数据的记录与重试规则 |
| 最终测试 | 查看时机、已查看情况，以及后续确认数据安排 |

统一协议不等于强制相同学习率或 tokenizer。方法有合理的专属训练设置时保留并披露；公平体现在共同任务、划分、指标、选择规则和可比的资源/调参机会。

## 可比性与复现判断

- 同协议、充分执行且公平比较的方法可直接排名。
- 外部数据、预训练规模或预算不同，分组展示或明确限定比较，不能将差值归因于算法。
- 论文报告分数单列为 reported-only，不作为本项目实际运行、不计入完整运行数量。
- 原任务复现差异检查版本、split、预处理、训练、评测与随机性；跨任务迁移只说明本项目结果，不能要求匹配原论文分数。
- 低分先排查实现、数据、评测和欠调参；失败地图只把排查后仍成立的模式当作研究线索。
- 协议改变保留旧版和原因。受影响方法需要重跑；新旧协议不拼成一张统一排名。

## 运行最低要求

保存实际命令、配置、环境、数据/split 标识、方法/代码版本、seed、选模型规则、资源、日志和度量 artifact。指标实现先用可手工检查样本验证；可行时从保存预测复算指标。

每个方法先 smoke 再正式运行。失败也占据结果矩阵一行；空缺值保持空缺，不能当零或插补。重试是新的运行记录，修复不得暗改标签、split 或研究主张。

迭代创新只用训练/开发结果。已用 final test 找弱点或筛方案时，写明已消耗，安排独立确认或保持探索结论；预先固定评测代码并不能抵消测试集适应性使用。
