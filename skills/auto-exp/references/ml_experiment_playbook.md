## 1. 实验证据是第一纪律

每个实验必须留下三类证据：

1. **运行设置**：数据版本与窗口、split、代码版本、配置、初始化参数、超参数、随机种子和输出路径。
2. **结果**：主指标、约束指标、业务指标、切片指标，以及选模所依据的 split 和 epoch。
3. **结论**：是否超过固定基线、证据是否独立、为什么继续或停止、下一步是什么。

失败、提前停止和环境错误也必须记录。保留完整错误、失败阶段、已完成产物和是否允许重试，避免后续重复踩坑。

## 2. 先定位改动层级

动手前回答两个问题：是否扩大了模型可用的信息边界；处理发生在模型外还是模型内。

| 层级 | 改动对象 | 信息边界 | 典型例子 |
|---|---|---:|---|
| L1 数据扩展 | 信息从哪里来 | 扩大 | 新字段、外部数据、跨系统历史 |
| L2 特征工程 | 固定输入坐标 | 不变 | 统计量、分桶、固定 embedding |
| L3 表示学习 | 模型如何组织输入 | 不变 | 时序、图、attention、门控 |
| L4 问题建模 | 任务和决策形式 | 不变 | point 到 ranking、static 到 dynamic |

哪一层都不涉及的改动通常只是调参。一次比较尽量只改变一层或一个核心变量；若不可避免地同时改变多项，明确写出归因混杂。

L1 信息必须在真实推理时可得。训练期监督不能伪装成推理期输入。

## 3. 分开测量信息红利与架构红利

数据中已有但模型从未使用的信息第一次进入模型，属于信息激活。正确对照是：

| 阶段 | 方法 | 测量对象 |
|---|---|---|
| baseline | 不使用新增信息 | 原始能力 |
| simple integration | 统计量、mean pooling 或简单模型 | 信息红利 |
| learned integration | 时序、图、attention 等 | 架构红利 |

如果跳过简单接入，复杂模型的收益不能全部归因于架构。

## 4. 实验协议由项目合同决定

通用规范不预设“固定 epoch”“必须早停”“只看 test”或固定 train/validation/test 结构。每个项目必须显式声明：

- **training split**：用于参数优化的数据。
- **selection split**：用于 early stopping、checkpoint、阈值或超参数选择的数据；可为空。
- **evaluation split**：用于报告性能的数据。
- **final holdout**：从未参与选择的独立最终评估集；可为空。
- **selection rule**：固定 epoch、最佳 epoch、固定阈值或其他规则。
- **reporting rule**：报告哪个 split、哪些指标、是否带置信区间或重复种子。

结果口径使用两个独立字段：

- `selection_exposure`：该 split 是否以及如何影响 epoch、checkpoint、阈值、超参数或 go/no-go 决策；没有则写 `none`。
- `evaluation_independence`：写 `independent` 或 `non-independent`，并记录理由。

若 evaluation split 参与了任何选择或反复反馈，`selection_exposure` 不能写 `none`，且 `evaluation_independence` 必须写 `non-independent`。不能仅用 `selected` 一词替代独立性披露。

模型参数保留、清理和晋级依据也必须在合同中声明，不得默认按 test、validation 或单一指标决定。

## 5. 先调研，再动手；限制调参循环

- 新方向先查旧实验和必要文献，确认是否已有可复现方法。
- 优先复现可信方法，再做任务适配；区分官方实现、结构复用和本地简化代理。
- 每个设计说明参考来源、任务适配和不可避免的偏离。
- 预先声明同一方向的搜索预算。项目未规定时，以少量有信息量的试验为默认，而不是无限追分。
- 超过预算仍无稳定改进时，回到数据、表征、任务定义或瓶颈分析，不继续盲目调参。

## 6. 预注册止损与运行控制

止损条件必须在启动前定义，例如训练不稳定、关键指标显著低于基线、资源超预算或数据审计失败。

没有可判断结果或预注册信号时，只做只读监控，不得自行暂停、杀进程、替换运行、缩短 epoch 或重启。若 trainer 不保存中间状态，先说明停止意味着什么，再请求决策。

出现异常时：

1. 保存完整 traceback、命令、配置和运行状态。
2. 区分代码错误、数据错误、环境错误、资源错误和科学合同错误。
3. 先在最小范围修复并验证可复用代码。
4. 使用新的 attempt 或 run identity 重试，不覆盖失败证据。
5. 若修复会改变科学合同，停止并请求确认。

## 7. 执行、产物与工程结构

### 可复现执行

- 复用代码、配置、prompt 和数据构造逻辑必须进入项目的可追踪来源后再执行。
- 长任务使用稳定的 run identity、独立日志和输出目录。
- 标准输出应包含阶段、进度、指标、产物和错误标记，便于自动监控。
- 远端只是执行环境时，不在远端临时修改可复用源文件。

### 最小产物集合

项目可以改文件名，但应覆盖这些逻辑角色：

- 完整运行配置与命令
- 数据、代码和关键输入指纹
- 环境指纹：lockfile 或容器，以及关键 runtime、framework、驱动和加速器版本
- 训练历史
- 选择规则与最佳 checkpoint 元数据
- 完整指标与切片指标
- 预测结果或可验证摘要
- 数据、shape、finite、截断和泄漏审计
- 完整运行日志
- 状态与失败原因

### 清理纪律

- 运行中不主动删除 checkpoint、adapter、模型权重、预测或审计证据。
- 先输出清理建议：路径、原因、风险、预计回收空间和依赖关系。
- 实际删除必须符合项目授权规则；高风险或不可逆删除需要明确授权。
- 删除后记录时间、路径、原因、授权和回收空间。

### 工程边界

- 模型、trainer、dataset、data preparation、evaluation 和 orchestration 保持明确边界。
- 当新实验改变 batch contract、标签、loss、评估或产物协议时，优先建立清晰的新入口，而不是向旧入口持续添加互斥 flag。
- 只把稳定复用的 primitive 放进公共模块；带实验语义的逻辑保留在实验实现中。
- 定期审计巨型文件、废弃分支、重复配置和失效路径。

## 8. 通用红线

### 数据泄漏

未来信息、结果标签和事后才能确定的信息只能作为允许的训练监督，不能作为线上或回测时不可得的输入。所有历史特征必须以预测时点截断。

### 对照漂移

固定可信基线及其数据、split、指标和代码版本。比较时说明除目标变量外是否还有变化。

### 选择偏差

任何参与选择的 split 都不是独立最终测试集。反复查看并据此改模型，也构成反馈。

### 证据夸大

语法检查、smoke、局部样本、代理标签和正在运行的作业不能被描述为正式完成结果。

### 权限扩大

“运行实验”不自动授权额外花费、停止其他任务、删除参数、覆盖结果、关机或发布代码。

## 9. 每个实验开跑前的检查

- [ ] 核心假设和唯一变量是什么？属于 L1/L2/L3/L4 还是调参？
- [ ] 数据版本、样本数、时间边界、标签和 split 是否锁定？
- [ ] 推理输入中是否含未来或结果信息？
- [ ] 固定基线和噪声尺度是什么？
- [ ] training、selection、evaluation、final holdout 各自是什么？
- [ ] 固定 epoch、早停、选模和阈值规则是否写清？
- [ ] 搜索预算、止损线和重试边界是否写清？
- [ ] 依赖、路径、shape、token、显存、磁盘和输出冲突是否预检？
- [ ] 当前请求或项目规则是否授权 smoke？若已运行，是否确认它不等于正式结果？
- [ ] 产物、日志、同步和授权边界是否明确？

## 10. 标准实验闭环

```text
提出问题
→ 检查旧实验与文献
→ 锁定实验合同和固定基线
→ 数据、泄漏、资源与 smoke 预检
→ 启动独立 run
→ 只读监控与异常诊断
→ 按预注册规则选择或停止
→ 验证指标、预测、配置、审计和日志
→ 与固定基线比较并标注证据边界
→ 写回实验日志
→ 继续 / 重试 / 止损 / 归档
```

没有完整状态回写和证据链的运行，不视为可复用实验。
