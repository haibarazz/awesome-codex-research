# 实验开跑前确认清单

## 方向级约束

- [ ] **研究问题**：这个方向要解决的具体瓶颈是什么？
- [ ] **固定基线**：对照实验、主指标和当前数值是什么？
- [ ] **有效提升阈值**：主指标至少提升多少才算超过噪声，而不是随机波动？
- [ ] **搜索预算**：这个方向最多运行 `<N>` 轮；未单独约定时，默认最多 **3 轮**。
- [ ] **方向止损**：连续 `<N>` 轮没有超过有效提升阈值时，停止继续调参，回到数据、表征、模型假设或任务定义重新分析。
- [ ] **资源预算**：最多使用多少 GPU 小时、API 费用、存储空间或并行任务？

## 本次实验合同

- [ ] **唯一变量**：相对固定基线，本次主要改变什么？是否混入其他变化？
- [ ] **数据口径**：数据版本、标签、样本数、时间范围和 split 是否锁定？
- [ ] **泄漏检查**：所有输入在预测时点是否真实可得？
- [ ] **训练与选择规则**：固定 epoch、early stopping、checkpoint、阈值和调参规则是否明确？
- [ ] **评估口径**：training、selection、evaluation 和 final holdout 分别是什么？是否需要标记为 non-independent？
- [ ] **单次止损线**：出现哪些指标、异常或资源信号时可以提前停止？

## 工程与收尾

- [ ] **运行身份**：experiment ID、run ID、attempt ID 和输出目录是否唯一？
- [ ] **预检通过**：路径、依赖、shape/token、显存、磁盘、样本数和 smoke 是否检查？
- [ ] **产物明确**：配置、指标、history、predictions、audit 和完整日志写到哪里？
- [ ] **权限明确**：谁可以启动、重试、停止、覆盖、删除、同步或关机？
- [ ] **日志位置**：实验完成或失败后，结果写入哪个实验日志？

只有所有必需项都有具体答案，才进入正式运行。
