# Prompt：问题与理论视角文献线

## 目标

根据用户的数据、场景和研究问题，找出研究必须进入的 **1–2 条核心问题／视角文献流**：谁已经研究过这个现象，哪些理论解释它，用户工作准备改变什么认识。先用于检索设计，再用于全文校准。

## 输入

- 数据对象、行动者、场景、分析单位、时间结构、结果变量。
- 用户的研究问题、拟解决的现实／决策困难、暂定贡献。
- 可选：候选论文全文，重点是 Introduction、Literature Review、理论与贡献段。

## A. 检索前：生成候选文献流

1. 用一句话重写研究锚点：`在[情境]中，观察[对象／行为]，试图解释或改善[问题／结果]。`
2. 分别提出候选流：
   - **问题／现象流：** 哪个稳定研究共同体正在讨论相同现象、决策或结果？
   - **理论／视角流：** 哪个机制、构念或理论能解释该问题，并可能约束设计？
3. 每条候选流给出：学界可识别的名称、与用户研究的关系、纳入／排除边界、2–4 组查询式、可能的相邻词与反向机制。
4. 候选可多于两条；初筛后只保留直接参与研究问题与贡献定位的 1–2 条，其余标为背景或待定。

## B. 取得全文后：校准每篇论文

对每篇论文提取：

- **研究锚点：** context、数据与单位、现象化研究问题、一句话定位。
- **核心文献流：** 代表文献与原文位置；已有知识；作者指出的缺口；本文怎样接入；该流承担“定义现象／提供理论／建立结果重要性／限定情境”中的哪种作用。
- **定位句：** `在[情境]中，本文连接[文献流 A]与[文献流 B]，研究[问题]，试图补足[缺口]。`
- **检索回写：** 新增关键词、遗漏的邻近流，以及应删除的伪相关流。

## 判断规则

- 不把论文所有小节或被引文献都升级为文献流；行业名称只有形成稳定研究问题时才单列。
- 理论若生成了表示、变量、约束、损失或交互要求，才是核心视角；只用于一句动机时降为背景。
- 作者明确表述与阅读者归纳分开；重要判断附 PDF 页码、章节或表图。
- 这一 prompt 不展开算法最近邻；技术机制与数据挑战交给技术 prompt。
